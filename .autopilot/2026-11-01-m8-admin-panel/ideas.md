# Идеи развития M8

Дата: 2026-11-01. Приоритеты: **P1** — делать следующим циклом (деньги/риск/удержание), **P2** — ближайшие кварталы (рост), **P3** — бэклог (когда созреет).

## Уже покрыто текущей сборкой — повторно не предлагать

Админ-панель (вход по паролю с PBKDF2-хешем, вкладки Дашборд/Пользователи/Премиум/Настройки), дашборд KPI + график активности, экран «Моя статистика», Блиц-спринт, Тренажёр дебютов, бесконечный Генератор матов, доводка «Игры с другом» (имена, реванш, счёт серии, отмена хода), чистка эмодзи и README (65 задач, порт, ₽), удаление LOCAL_ADMIN. Также этой сборкой не предлагаются повторно: бэкап всех данных через экспорт/импорт JSON и промокоды (локальные).

## Идеи

### P1 — следующий цикл

1. **Серверные промокоды и премиум.** Перенести промокоды и выдачу плана в Supabase (таблица + edge-функция, RLS для роли admin), оставив локальный режим как fallback. — *Зачем:* локальные промокоды подделываются через devtools за минуту, а это единственная монетизация продукта.
2. **Облачная синхронизация прогресса.** Таблица `progress` (user_id → JSON), запись по дебаунсу, конфликт — «последняя версия побеждает» с ручным выбором через существующий TransferCard. — *Зачем:* сейчас очистка браузера или второе устройство обнуляют месяцы прогресса — главный источник оттока.
3. **Гигиена репозитория и секретов.** Ротация Supabase-токена (скрипт уже есть), чистка git-истории (git filter-repo/BFG), удаление `rus.traineddata` (5 МБ) и презентационных devDeps (tesseract, pdf-lib), вычистка мёртвого поля `password?` в локальных пользователях. — *Зачем:* утёкший токен в истории — открытая дверь, а мусор в репо удорожает каждый клон и аудит.
4. **CI-конвейер.** GitHub Actions: `npm run check` на каждый PR + сборка dist. — *Зачем:* delivery gate существует, но выполняется только на совести исполнителя; один красный PR сейчас можно слить молча.

### P2 — рост

5. **Онлайн-игра с другом по коду.** Realtime-канал Supabase (или WebRTC): комната по короткому коду, тот же `PlayScreen`-hotseat UI. — *Зачем:* «играть с живым человеком» — самое частое ожидание от шахматного приложения, сейчас его нет совсем.
6. **Push-напоминания о стрике и миссиях.** PWA push через сервис-воркер + выбор времени в настройках; локальные уведомления как офлайн-вариант. — *Зачем:* стрик — ядро удержания, но без напоминания он умирает после первого пропущенного дня.
7. **Честные рейтинговые сезоны лиги.** Заменить фейковых ботов `leagueBots` на агрегированную статистику реальных игроков (при включённом Supabase), сезон — неделя, дивизионы уже есть. — *Зачем:* игроки быстро распознают «подставных» соперников, и главный крючок Duolingo-модели работает только с реальной конкуренцией.
8. **Конвейер контента: автоимпорт задач из Lichess API.** Развить существующий `scripts/lichess-import.mjs` до команды «добрать N задач по теме и рейтингу» с валидацией (`validate-puzzles.mjs`) и авто-подсказками от движка. — *Зачем:* 65 задач выгорают за неделю активной игры, а ручное наполнение не масштабируется.
9. **Разбор партии после игры.** По завершении партии с ИИ прогнать ходы через движок и показать 3 худших хода игрока с коротким пояснением (по образцу CoachTip). — *Зачем:* превращает каждую проигранную партию в урок и переиспользует уже построенный движок почти бесплатно.
10. **Расширение «Моей статистики» до аналитики тем.** График решаемости по темам за 8 недель + рекомендация «что тренировать» из тетради ошибок. — *Зачем:* данные уже собираются в `mistakes` и `activityLog`, а игроку сейчас видно только сырой счётчик.

### P3 — бэклог

11. **Редактор контента в админке.** CRUD задач/уроков поверх локального JSON + экспорт патчем в репозиторий. — *Зачем:* наполнение без релиза пригодится, когда контент-конвейер (идея 8) перестанет успевать за запросами.
12. **Триал премиума и A/B цен.** 7 дней премиума бесплатно при регистрации; эксперименты с ценами 299/1990/3990 ₽ только в связке с серверными промокодами (идея 1). — *Зачем:* конверсия в оплату сейчас нечем измеряться и не с чего начаться.
13. **Лидерборды и достижения на сервере.** Таблицы достижений в прогрессе (сейчас они только в UI), глобальный топ по XP/спринтам за сезон. — *Зачем:* социальное сравнение усиливает и лигу, и спринт, но требует облака — имеет смысл после идеи 2.
14. **Публикация в сторы.** Довести Capacitor-сборку до Google Play (Tauri-сборку .exe — до инсталлятора с подписью). — *Зачем:* PWA не находится в поиске сторов, а органический трафик шахматных приложений живёт там.

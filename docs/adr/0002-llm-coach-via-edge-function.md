# ADR-0002: LLM-тренёр через Supabase Edge Function с двухуровневым кэшем

**Статус:** принято (2026-08-21)

## Контекст

Приложению нужен ИИ-тренер: подсказки в задачах, разбор ошибок, итоги
партий. Провайдер — любой OpenAI-совместимый API (OpenAI/DeepSeek/OpenRouter).
Требования: ключи не покидают сервер, офлайн-PWA не ломается, стоимость
вызовов контролируется, монетизация завязана на Premium.

## Решение

1. Edge Function `ai-coach` (Deno): auth → серверный кэш (`coach_cache`,
   ключ sha-256 от `PROMPT_VERSION|action|lang|fen|…`) → дневная квота
   (`coach_usage`: free 5 / premium 50) → вызов провайдера (секреты
   `AI_PROVIDER_KEY`, `AI_PROVIDER_URL`, `AI_MODEL`) → строгая валидация
   JSON `{title, text}` → запись в кэш.
2. Клиент (`src/ai/coach`): сначала localStorage-кэш (30 дней, тот же ключ,
   что на сервере) — попадание отвечает мгновенно, офлайн и без квоты;
   промис-модель повторяет `cryptoPay.ts` (типизированные причины ошибок).
3. Промпты версионируются (`PROMPT_VERSION`): смена формулировок инвалидирует
   оба кэша разом, без ручной чистки.
4. Попадание в серверный кэш не списывает квоту — популярные объяснения
   к задачам бесплатны для всех после первого запроса.

## Альтернативы

- Прямые вызовы LLM из клиента — отвергнуто: ключ в бандле = утечка.
- Локальная LLM (WASM) — отвергнуто: сотни МБ в офлайн-PWA, слабые
  мобильные WebView.
- Отдельный бэкенд — отвергнут: проект уже на Supabase, edge functions
  решают задачу без новой инфраструктуры.

## Последствия

- UI-точки: `CoachTip` в ChessPuzzle (hint), ReviewScreen (explain),
  PlayScreen (review после партии). Без Supabase кнопка скрыта.
- Квоты управляются секретами (`AI_COACH_FREE_LIMIT`/`AI_COACH_PREMIUM_LIMIT`),
  статус Premium определяется таблицей `subscriptions` на сервере.

# ADR-0006: Активность — поле activityLog внутри UserProgress с backfill

**Статус:** принято (2026-11-01)

## Контекст

Админ-дашборду нужны «активные за 7 дней» и график за 14 дней, «Моей
статистике» — календарь за 8 недель. Прогресс офлайн-first в localStorage
у каждого пользователя; старые профили без новых полей обязаны продолжать
читаться.

## Решение

Активность хранится полем `activityLog: Record<'YYYY-MM-DD', number>`
прямо в `UserProgress`; инкремент — в единой внутренней точке `bumpActivity`
внутри `completePuzzle` и `noteExternalSolved`. `normalize()` при загрузке
дозаполняет `activityLog` (и `sprintBest`, `openingsStudied`) старым профилям;
`normalize()` экспортирован как чистая функция для теста backfill.

## Почему

- **Отдельный лог событий (append-only event store)** — отклонён: это вторая
  параллельная структура хранения, которую пришлось бы протаскивать через все
  существующие швы жизненного цикла профиля — экспорт/импорт, сброс прогресса,
  удаление пользователя, админский бэкап всех `chessup-*` ключей. Активность
  по своей судьбе — часть прогресса пользователя, а не поток событий
  приложения; агрегаты (7/14 дней, 8 недель) считаются одним проходом по
  записи «дата → счётчик».

## Последствия

- `activityLog` никем не подчищается и растёт неограниченно (медленно —
  365 записей в год на пользователя).
- Активность живёт и умирает вместе с профилем: сброс прогресса обнуляет
  и графики.
- Счётчик — «решённые задачи», а не «сессии»: день с одной задачей уже
  активный день.
- Backfill в `normalize()` теперь обязательный ритуал: любое новое
  обязательное поле `UserProgress` без дозаполнения валит старые сохранения.

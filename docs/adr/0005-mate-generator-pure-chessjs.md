# ADR-0005: Генератор матов — чистый перебор на chess.js с seed и fallback-банком

**Статус:** принято (2026-11-01)

## Контекст

Бесконечный режим «Генератор матов» требует поток легальных позиций
с верифицированным матом в 1–2. В проекте уже есть собственный боевой движок
(ADR-0001/0003: negamax + альфа-бета в Web Worker, гарантированно находит
мат в 1–2 на уровне 8).

## Решение

Генерация — чистым синхронным модулем `src/game/mateGen.ts` без React и без
воркера: детерминированный ГПСЧ (mulberry32 по seed) выбирает наборы фигур
и клетки → проверка легальности на chess.js → верификация forced-мата
перебором (`verifyMateInN`, для мата в 2 проверяются все ответы противника);
не вышло за ≤200 попыток — позиция берётся из `FALLBACK_BANK` (10 проверенных
позиций, 5+5). Одинаковый seed — одинаковая выдача; модуль покрыт юнит-тестами
без воркера.

## Почему

- **Боевой движок M8 как генератор** — отклонён: движок живёт в Web Worker
  с RPC-клиентом и бюджетом 120–800 мс на вызов; генерация мата в 2 требует
  десятков verify-вызовов на позицию и сотен позиций — очередь воркера,
  асинхронная сложность и тайминги в UI. Семантика тоже другая: движок ищет
  лучший ход, генератору нужно доказать forced-мат по всем веткам.
  Юнит-тесты детерминизма и легальности с воркером существенно сложнее.
- **Кастомный мини-движок внутри генератора** — отклонено: дублирует
  chess.js-перебор; chess.js уже даёт легальность и проверку мата.

## Последствия

- Мат-в-2 генерируется 0,5–1 с на главном потоке; потребитель обязан готовить
  следующую позицию заранее, иначе видна пауза «Generating».
- Фиксированный набор фигурных составов: при исчерпании попыток позиции берутся
  из банка из 10 — регулярный игрок увидит повторы.
- Детерминизм — контракт: нельзя менять порядок вызовов ГПСЧ или составы фигур
  без ломания воспроизводимости seed.

# ADR-0009: Данные админ-панели — чистый модуль admin/store без React

**Статус:** принято (2026-11-01)

## Контекст

Панели нужны данные из чужих localStorage-прогрессов, промокодов, планов
и опционально Supabase, а витрина — четыре вкладки. В проекте нет
компонентных тестов (testing-library в devDeps не используется), но есть
проверенный шаблон React-free слоя — `src/ai/engine`.

## Решение

Вся работа с данными панели — через чистые модули `src/admin/store.ts` и
`src/admin/auth.ts` без React: они владеют именами ключей и шейпами хранения,
компонентам отдают только функции (`listLocalUsers`, `readProgressFor`,
`aggregateDashboard`, `validatePromo`, `verifyAdminPassword`, …).
`aggregateDashboard()` — синхронный и локальный; Supabase-счётчики вкладка
Дашборда складывает отдельно через `listSupabaseUsers()`.

## Почему

- **Сбор и агрегация прямо в компонентах/хоках админки** — отклонено:
  агрегация зажата в render-цикл и жизненный цикл React, тестировать можно
  только компонентами — а компонентного тестирования в проекте нет.
  Чистый модуль тестируется на фикстурах прогресса напрямую
  (`store.test.ts`: `validatePromo`, `aggregateDashboard`), переиспользуется
  всеми вкладками и повторяет шов `ai/engine`, уже принятый в проекте.

## Последствия

- Знание о ключах дублируется: `admin/store.ts` читает `chessup-progress:*`
  напрямую, мимо `useProgress` — переименование или смена шейпа ключа надо
  вносить в два места (это зафиксировано в интерфейсах).
- Модуль не реактивен: перечитывание после чужих изменений — ручное,
  через window-события (`chessup-plan-changed`) и перезапросы вкладок.
- TTL сессии не протухает сам: панель обязана спрашивать
  `adminSessionActive()` при навигации.
